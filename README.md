# netpult

Один пульт для обхода блокировок: zapret, VPN и прокси Telegram в одном месте. Один бинарь, без рантайма и зависимостей.

```
  ОБХОД БЛОКИРОВОК

  ● zapret    ВКЛ    general_alt10.bat
  ● VPN       ВКЛ    туннель поднят
  ● Telegram  ВКЛ    192.168.1.10:1080

  НОДЫ  ↑↓ — выбор, Enter — включить, p — замерить
  ▸ ● 🇹🇷 Турция                306 мс
      🇩🇪 Германия              176 мс
      🇪🇪 Таллин                178 мс
      🇫🇮 Финляндия             молчит

  › vpn no
  ▸ vpn nodes   ноды с задержками
    vpn off     снять туннель
```

`netpult` без аргументов открывает этот экран. С аргументами — обычные команды для скриптов.

Одно окно, из которого никуда не уходишь. Внизу всегда строка ввода: набираешь
часть команды — под ней появляются похожие, стрелки выбирают, Enter выполняет.
Ищется подпоследовательностью, так что `внод` находит `vpn nodes`. Вставленная
ссылка сразу предлагает загрузить подписку.

Вывод команды печатается тут же, построчно по мере появления, — возвращаться
клавишей неоткуда. Долгие дела (замер задержек, подбор стратегии) идут в
стороне и не морозят экран, и всё это время видно, что именно проверяется
сейчас и сколько осталось: замер двух десятков нод занимает под минуту, и
молчание в это время читается как зависание.

Пока строка пустая, стрелки ходят по нодам, Enter включает выбранную, `p`
меряет задержки, `r` обновляет состояние, `q` выходит.

## Автоподбор

`netpult tune` перебирает стратегии и смотрит не на теорию, а на факт: открывается ли YouTube и с какой скоростью отвечает CDN. Текущая проверяется первой — если она в порядке, ничего не меняется.

Скорость мерится дважды, берётся лучший замер, и рабочая стратегия не уступает место кандидату, пока тот не обгонит её в полтора раза. Без этого запаса пульт дёргал бы настройку из-за случайной просадки: в первом же прогоне рабочая стратегия показала 51 КБ/с на холодном соединении и 202 КБ/с на следующем замере.

## Через что идёт интернет

Обход бывает не один. Он может стоять на роутере, рядом может работать чужой
VPN, в переменных среды может висеть прокси — и всё это перекрывает друг друга.
Классическое «включил zapret, а лучше не стало» почти всегда про это.

```
netpult path
```

Показывает маршрут по умолчанию (и забрал ли его туннель на себя), внешний
адрес, DNS, что включено на этом компьютере, и отдельно — что делается со
стороны сети. В конце называет конфликты: zapret при поднятом туннеле не
делает ничего, два туннеля дерутся за маршрут, системный прокси уводит часть
программ мимо туннеля.

Пока свой обход включён, чужой не разглядеть: трафик и так исправлен. Для
точного ответа есть `netpult path --deep` — снимает свой zapret на пару секунд,
проверяет заблокированное и возвращает как было. Если открывается и без него —
обход стоит выше, на роутере или у провайдера, и свой можно не держать.

Вердикт запоминается по сети: в следующий раз в той же сети пульт скажет, чем
она оказалась, и когда это проверялось. Отчёт про дом и про кафе иначе выглядит
одинаково, а разница между ними как раз в этом.

## Шифрованный DNS

```sh
netpult dns on
```

Поднимает свой резолвер на `127.0.0.1:5335` и переводит на него систему. Дальше
шифрование получают все программы разом — любой браузер, Steam, что угодно без
своих настроек. Галочку «DNS через HTTPS» в браузере включать не нужно, и не
важно, есть ли она там вообще.

Российские зоны нарочно резолвятся российским DNS: иначе банки, прячущие
записи от иностранных резолверов, перестают открываться. Тот же сплит стоит на
роутере и по той же причине. Спрашиваем его тоже по DoH — с августа 2026 ТСПУ
перехватывает обычный DNS на 53 и отвечает вместо того, кого спросили, так что
открытый путь стал не просто нешифрованным, а недостоверным. Российским
резолвер при этом быть не перестал: наружу мы выходим со своего адреса.

Штатный путь Linux — `systemd-resolved` с DNS-over-TLS — не годится: порт 853
у российских провайдеров закрыт, а DoH по 443 работает. Поэтому резолвер свой,
на том же ядре sing-box, что и туннель.

```sh
netpult dns test
```

```
  ✓ система спрашивает   127.0.0.1:5335 — это мы
  ✓ резолвер отвечает    example.com → 8.6.112.0 за 0 мс
  ✓ канал наружу         1.1.1.1:443 — шифрованный DoH
  ✓ российские зоны      77.88.8.8:443 — тоже DoH, чтоб банки жили
```

Проверка смотрит на живые соединения, а не на время ответа: по времени не видно
ничего — кэш отвечает мгновенно, а несуществующее имя в российской зоне
отвечает дольше заграничного.

`netpult dns off` возвращает DNS своей сети.

Работает на всех трёх системах, но по-разному — потому что по-разному
устроена вторая половина дела, способ сказать системе «спрашивай его»:

| | чем сказано системе | порт резолвера | чем держится |
|---|---|---|---|
| Linux | `systemd-resolved` | 5335 | systemd |
| macOS | `networksetup` | 53 | launchd |
| Windows | `netsh` | 53 | служба |

`systemd-resolved` принимает адрес вместе с портом, поэтому на Linux резолвер
живёт на непривилегированном 5335. `networksetup` и `netsh` порт задать не
умеют — только адрес, — значит на маке и Windows слушать приходится 53, и
служба там поднимается от администратора.

Включение везде идёт с проверками и откатом: конфиг проверяется самим ядром,
система переводится только после того, как резолвер ответил на настоящий
запрос, и возвращается назад, если после перевода резолвинг встал.

> Маковская и виндовая половины собраны и проверены сборкой под свои цели, но
> на живых машинах не гонялись — ни мака, ни Windows под рукой не было. Linux
> проверен вживую, включая цикл включения и выключения.

## Звонки в Telegram

Прокси MTProto (`netpult tg on`) ведёт переписку, но не голос: разговор идёт
отдельными UDP-пакетами к голосовым серверам и мимо прокси. Поэтому знакомая
картина — сообщения ходят, звонок не встаёт.

```sh
netpult calls         # чем прикрыты звонки сейчас
netpult calls on      # починить
netpult calls off     # вернуть как было
```

`calls on` поднимает **точечный туннель**: через ноду уходит только Telegram,
весь остальной интернет идёт напрямую — без лишних задержек и без адресов
датацентра там, где их не любят. Адреса Telegram берутся официальным списком
`core.telegram.org/resources/cidr.txt` и обновляются сами: голос ходит по
адресам, минуя имена, и одних доменных списков мало.

`calls on --dpi` — путь без ноды: к текущей стратегии дописывается блок для
голосовых портов (UDP 590-1400, 3478, фильтр `stun`). Помогает, только если
провайдер режет звонки разбором пакетов. Если диапазоны Telegram закрыты по IP
— а автор zapret говорит именно об этом, — дурить нечего, и путь не поможет;
плюс при разговоре напрямую между собеседниками обход нужен обоим.

## Что сломано

```sh
netpult doctor        # осмотр: что измерили, что сломано, чем чинится
netpult doctor --fix  # и сразу починить безопасное
```

У каждой строки осмотра есть причина, а не только вердикт: не «Telegram не
работает», а «149.154.167.51:443 не отвечает — соединение не встаёт». Порядок
проверок — по порядку поломки: сначала связь по адресу, потом разрешение имён,
потом зависимости, взаимные помехи, стратегия, Telegram, нода, DNS, сторож.

## Сторож

`netpult watch install` ставит фоновую службу, которая раз в десять минут смотрит, живо ли всё, и чинит по лестнице от дешёвого к дорогому: поднять упавший прокси Telegram → включить выключенный zapret → перезапустить движок → подобрать другую стратегию. Каждый шаг пишется в журнал, `netpult watch log` его показывает.

Он же следит за сменой сети: пришёл в другое место — включается профиль этого места.

## Профили сетей

Профиль привязан к имени Wi-Fi (а если его не видно — к адресу шлюза) и помнит, что в этой сети должно быть включено. Настроил как надо, сказал `netpult profile save` — дальше пульт сам приведёт всё к этому виду, когда ты сюда вернёшься.

## Раздача на телефон

`netpult share on` поднимает HTTP-прокси на всю локальную сеть. В настройках Wi-Fi телефона указываешь узел и порт — и весь трафик телефона выходит в интернет с этого компьютера, а значит, проходит через zapret. Ни VPN, ни root на телефоне не нужны.

Прокси свой, без библиотек: `CONNECT` для HTTPS и обычные запросы для HTTP — это всё, что нужно настройкам Wi-Fi на Android и iOS.

**Раздача всегда под паролем.** Открытый прокси на всю сеть означал бы, что любой сосед по Wi-Fi выходит в интернет через тебя, — такого не нужно. Поэтому `net share on` требует пароль, и если ты его не задал, netpult заводит свой и показывает при включении. Пароль вводится в телефоне там же, где адрес прокси. Свой можно прописать в настройках (`share_password = ...`). Если очень надо открыть без пароля — только явной командой `net share open`.

## Своё ядро вместо клиента

Happ ставится не везде: на macOS 11 его нет и не будет, а подписку он же и
держит. Поэтому netpult умеет обходиться без него — разобрать подписку сам и
собрать конфиг для sing-box.

`netpult vpn sub <ссылка>` скачивает подписку и понимает всё, что ходит в
природе: base64-блоб со ссылками, простой список `vless://` `vmess://`
`trojan://` `ss://`, YAML Clash, выгрузку sing-box, выгрузку xray и SIP008.
Панель отдаёт разное в зависимости от того, кем представился клиент, поэтому
запрос повторяется с разными User-Agent (`sing-box`, `Happ`, `v2rayNG`,
`clash-verge`, `Shadowrocket`), пока не придёт разбираемое. Так подписка
читается независимо от того, под какое приложение её выдали.

Из нод собирается конфиг с TUN-туннелем (весь трафик, включая UDP и игры),
селектором для выбора ноды на ходу через clash API, автоподбором по задержке и
российским сплитом: домены и адреса РФ идут напрямую, мимо ноды.

Дальше пульт управляет туннелем сам, и Happ больше не нужен:

```sh
netpult vpn core install    # ядро sing-box под свою систему
netpult vpn sub <ссылка>    # подписка
netpult vpn on              # туннель (TUN требует sudo)
netpult vpn nodes           # ноды с задержками, текущая помечена
netpult vpn use             # выбрать ноду стрелками, с поиском и задержками
netpult vpn use Турция      # или сразу — номером либо частью имени
netpult vpn auto            # выбирать самую быструю самому
netpult vpn update          # перечитать подписку
```

Задержки и переключение идут через clash API самого движка, без перезапуска —
соединения переезжают на новую ноду на ходу.

**Подписки с учётом устройств.** Панели вроде Remnawave отдают настоящие ноды
только клиенту, который присылает идентификатор устройства; остальным приходит
заглушка «Приложение не поддерживается». netpult шлёт свой постоянный
идентификатор (`~/.local/share/netpult/hwid`) и потому получает настоящий
конфиг. Идентификатор занимает слот устройства в панели: чтобы не тратить два
слота на две машины, скопируй файл `hwid` со старой на новую.

**Ядро под старые macOS.** Официальные сборки sing-box требуют macOS 12 и на
Big Sur падают в dyld. Минимальную версию задаёт компилятор Go, а не машина
сборки, поэтому ядро для релизов собирается Go 1.24 — последним, который ставит
minos 11.0. Скрипт сборки — `tools/build-core.sh`.

Разбор JSON — свой, `src/json.rs`, как и всё прочее в этом бинаре. Конфиг
проверяется самим движком (`sing-box check`), а не верой в то, что схема
угадана правильно.

## Сплит-прокси

`net split on` поднимает локальный прокси, который смотрит на имя каждого хоста: домен из списка — гонит через заграничную ноду, остальное — напрямую, без крюка за границу. Ровно как домашний роутер. По умолчанию через ноду идут сервисы, которые режут по стране (OpenAI, Anthropic, Gemini), а не по DPI, — их zapret не лечит, тут нужен именно заграничный выход.

Ноду сплит не расшифровывает и не поднимает сам. У Happ, когда выбрана нода и он работает в режиме прокси, уже слушает SOCKS на `127.0.0.1:10808` — туда сплит и отдаёт нужные домены. Так HWID-замок Happ не трогается, а ротация нод работает сама. Адрес ноды-SOCKS настраивается: `split_upstream = ...`.

Список — два файла: твой ручной `split-domains.list` (правится `net split add` или руками) и автосписок геоблока `split-geoblock.list`. Второй наполняет `net split update`: тянет `itdoginfo/allow-domains` (~466 доменов ушедших из РФ сервисов — JetBrains, Adobe, Cursor, DeepL, Tidal…) с GitHub, а если тот молчит — с зеркал jsDelivr и gh-proxy. Сторож обновляет его раз в сутки. `net split log` показывает, что реально пошло через ноду, а что напрямую.

## Что умеет и на чём

| | Linux | macOS 11+ | Windows 10/11 |
|---|---|---|---|
| свой туннель (sing-box TUN) | да, `sudo` | да, `sudo` | да, окно администратора |
| подписки, ноды, задержки, автоподбор | да | да | да |
| `net path` — через что идёт интернет | да | да | частично: без маршрута по умолчанию |
| экран пульта | да | да | да |
| обход DPI (zapret) | да, через systemd-юнит | движок ставится отдельно | движок ставится отдельно |
| прокси Telegram | да | нужен tglock-cli | нужен tglock-cli |
| раздача на телефон, сплит | да | запуск вручную | запуск вручную |
| сторож в автозапуске | да | нет | нет |

Главное — туннель, подписки и выбор ноды — работает одинаково на всех трёх
системах: это и есть замена Happ там, где Happ не встаёт. macOS 11 Big Sur
поддержана намеренно: ядро собирается Go 1.24, который ставит минимальную
версию системы 11.0, тогда как готовые сборки sing-box требуют 12-ю и падают в
`dyld`.

Обход DPI — это [zapret](https://github.com/bol-van/zapret), и на разных
системах он перехватывает трафик по-своему: `nfqws` через NFQUEUE на Linux,
`winws` через WinDivert на Windows, `tpws` через PF на macOS (там нет UDP,
поэтому QUIC и голос Discord этим способом не лечатся — ограничение системы, а
не утилиты). Пультом сейчас управляется только линуксовый: на остальных
командам честно отвечают, что движок ведётся отдельно.

Раздача и сплит на Linux оформляются пользовательскими юнитами systemd; на маке
и в Windows их аналоги не подведены, но сами прокси запускаются руками:
`netpult share serve`, `netpult split serve`.

## Настройки

Всё определяется само: утилита ищет уже установленный zapret, бинарь `tglock-cli` и клиент Happ в обычных местах. Если что-то лежит иначе, можно указать явно в `config` рядом с состоянием (`~/.local/share/netpult/config`, на Windows `%LOCALAPPDATA%\netpult`, на macOS `~/Library/Application Support/netpult`):

```
zapret_dir = /home/deck/Apps/zapret-discord-youtube-linux-master
zapret_service = zapret_discord_youtube.service
tglock_bin = /home/deck/Apps/tglock/tglock-cli
tg_port = 1080
tg_lan = true
happ_bin = /opt/happ/bin/Happ
watch_interval_min = 10
share_port = 8899
share_password =
```

## Почему проверка идёт через curl

Стратегии zapret ломают часть TLS-клиентов. На `general_alt10` соединение rustls с `www.youtube.com` зависает намертво, тогда как curl, openssl и браузер проходят спокойно. Проверка на собственной криптобиблиотеке показывала бы «не открывается» там, где у человека всё работает, — поэтому запросы делает системный `curl`, который ведёт себя как настоящий клиент. Заодно в бинаре нет ни TLS-стека, ни его зависимостей.

## QR без зависимостей

`src/qr.rs` — свой кодировщик: байтовый режим, уровень коррекции L, версии 1–10 (до 271 байта). Матрицы сверены с libqrencode модуль в модуль, эталоны лежат в `tests/vectors.txt`, проверяются `cargo test`.

## Установка

Нужен бинарь `netpult` и три внешних куска, которыми он управляет: **zapret**
(обход DPI), **tglock-cli** (прокси Telegram) и по желанию **Happ** (VPN для
геоблока и нода для сплита). netpult их не тащит за собой — он находит уже
установленное и рулит им.

### 1. Поставить netpult

Готовые сборки лежат в [релизах](https://github.com/pepetutu1337/netpult/releases):
Linux x86-64 (статический, без зависимостей от glibc — идёт и на SteamOS, и на
Ubuntu, и на Alpine), macOS 11 Big Sur и новее (универсальный бинарь Intel +
Apple Silicon), Windows 10/11 x64.

**Linux и macOS:**

```sh
curl -fsSL https://raw.githubusercontent.com/pepetutu1337/netpult/main/install.sh | sh
```

**Windows** (PowerShell):

```powershell
irm https://raw.githubusercontent.com/pepetutu1337/netpult/main/install.ps1 | iex
```

Ставит бинарь в `~/.local/bin` и сразу докачивает ядро sing-box — после этого
`net vpn on` уже поднимает туннель, ничего доставлять не надо.

Команда не скачалась — значит, GitHub режут ровно так, как netpult и лечит.
То же через зеркало:

```sh
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/pepetutu1337/netpult/main/install.sh | sh
```

```powershell
irm https://gh-proxy.com/https://raw.githubusercontent.com/pepetutu1337/netpult/main/install.ps1 | iex
```

Сам установщик дальше тоже ходит через зеркала, так что достаточно, чтобы
скачался он один. Своё зеркало — `NETPULT_MIRROR=https://…/`.

<details>
<summary>Если GitHub не отдаёт вообще — поставить с флешки</summary>

Замкнутый круг: пульт лечит доступ к сети, а качается из той самой сети.
Зеркала спасают маленький установщик, но ядро — восемьдесят мегабайт, и через
них оно идёт по паре сотен байт в секунду, то есть никак.

Выход простой: скачать файлы на машине, где сеть в порядке, и принести.

На рабочей машине (подставь свою систему: `macos-universal`,
`linux-x86_64`, `windows-x86_64`):

```sh
v=v0.3.3
curl -fLO https://github.com/pepetutu1337/netpult/releases/download/$v/netpult-macos-universal.tar.gz
curl -fLO https://github.com/pepetutu1337/netpult/releases/download/core-1.13.19/sing-box-macos-universal
```

Оба файла — на флешку. На той машине:

```sh
curl -fsSL .../install.sh -o install.sh   # или тоже принести файлом
NETPULT_ASSET=./netpult-macos-universal.tar.gz \
NETPULT_CORE=./sing-box-macos-universal \
  sh install.sh
```

Ничего не качается, всё берётся из принесённых файлов: и метка карантина
снимается, и ядро кладётся куда надо.

</details>

Скрипт сам определит систему, скачает нужную сборку, сверит контрольную сумму и
положит бинарь в `~/.local/bin` (на Windows — в `%LOCALAPPDATA%\netpult\bin`,
добавив каталог в PATH). Следом он качает ядро sing-box под эту же систему
(отдельный релиз `core-1.13.19` — оно большое и меняется редко) — без него нет
ни туннеля, ни выбора ноды. Отказаться: `NETPULT_NO_CORE=1`,
поставить потом: `netpult vpn core install`. Проверка: `netpult version`.

После установки нужна только подписка:

```sh
netpult vpn sub https://адрес-подписки/...
netpult vpn on
```

Дальше всё живёт на одном экране — просто `netpult` (или `net`, если сделать
ссылку).

Ни Rust, ни компилятора, ни distrobox для установки не нужно — на SteamOS
статический бинарь просто скачивается и запускается.

> **Если GitHub не открывается.** Установщику netpult нужен доступ к тому же
> GitHub, ради которого netpult и ставят. Поэтому каждая загрузка идёт сначала
> напрямую, а потом через зеркала (`ghproxy.net`, `gh-proxy.com`, `ghfast.top`).
> Своё зеркало задаётся переменной `NETPULT_MIRROR`, конкретная версия —
> `NETPULT_VERSION=v0.3.0`, каталог установки — `NETPULT_BIN_DIR`.
>
> Файлы релизов лежат на `release-assets.githubusercontent.com`, и его в России
> режут жёстче остального GitHub — до сотен байт в секунду. Если установщик
> встал: поднять любой обход и повторить, либо собрать из исходников.

Руками, без скрипта: скачать `netpult-linux-x86_64.tar.gz` /
`netpult-macos-universal.tar.gz` / `netpult-windows-x86_64.zip` со страницы
релиза, распаковать, положить в любой каталог из PATH. На macOS скачанному
файлу нужно снять карантин: `xattr -d com.apple.quarantine netpult`.

<details>
<summary>Собрать из исходников</summary>

Нужен Rust 1.85+ (edition 2024) и системный компоновщик (`cc`).

```sh
git clone https://github.com/pepetutu1337/netpult.git
cd netpult
cargo build --release
install -Dm755 target/release/netpult ~/.local/bin/netpult
```

На SteamOS корневая система read-only и без `cc`, поэтому локальная сборка там
требует distrobox с тулчейном. Для обычной установки это не нужно — бери
готовый бинарь из релизов.

</details>

### 2. Всё, чем обходят

```sh
netpult deps            # что нужно пульту и что уже нашлось
netpult deps install    # поставить недостающее
```

Пульт держит три внешние программы и сам знает, где их брать:

| что | зачем | откуда ставится |
| --- | --- | --- |
| zapret | обход DPI: YouTube, Discord, звонки | [Sergeydigl3/zapret-discord-youtube-linux](https://github.com/Sergeydigl3/zapret-discord-youtube-linux) |
| tglock-cli | прокси Telegram без чужих серверов | [by-sonic/tglock](https://github.com/by-sonic/tglock) |
| sing-box | туннель, сплит, шифрованный DNS | своя сборка ([tools/build-core.sh](tools/build-core.sh)) |

Уже стоит своё — ставить заново не надо: поиск смотрит в папках программ,
в `~/Dev`, `~/Projects`, `~/Downloads`, в `PATH` и внутри склонированных
репозиториев (`target/release`). Если zapret распакован в нескольких местах
сразу, берётся тот, из которого запускается служба, а копии с `backup` в имени
отбрасываются. Свою установку можно назвать прямо:

```sh
netpult deps use zapret ~/Apps/zapret-discord-youtube-linux-master
```

**Если ничего не качается.** Файлы релизов GitHub лежат на
`objects.githubusercontent.com`, а этот диапазон закрыт в России по IP:
соединение не встаёт вовсе, и дурить DPI тут нечего. Пульт пробует по очереди
свой склад через jsDelivr, обычную ссылку и медленные зеркала. Когда закрыто
всё, принеси файл с любой машины с интернетом:

```sh
netpult deps install tglock ~/Downloads/tglock-cli-x86_64-unknown-linux-gnu
```

### 3. Happ (по желанию — для геоблока и сплита)

Поставь [Happ](https://github.com/Happ-proxy/happ-desktop), заведи подписку,
выбери ноду. Для сплита переведи Happ в режим прокси (не TUN), тогда он держит
локальный SOCKS `127.0.0.1:10808` — туда netpult и отдаёт домены из списка.

```sh
netpult vpn        # открыть окно клиента
netpult split on   # домены из списка через ноду, остальное напрямую
```

## Сборка

```sh
cargo build --release
cargo test            # 8 тестов: QR-вектора, SOCKS5, маршрутизация, base64/auth
```

Релиз собирает GitHub Actions (`.github/workflows/release.yml`) по тегу:

```sh
git tag v0.1.0 && git push origin v0.1.0
```

Он строит Linux на musl (статически), macOS универсальным бинарём с
`MACOSX_DEPLOYMENT_TARGET=11.0` и Windows на MSVC, кладёт архивы и файлы
`.sha256` в релиз и снимает черновик, когда все три собрались.
